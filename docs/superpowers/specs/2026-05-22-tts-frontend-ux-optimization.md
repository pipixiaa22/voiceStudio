# 语音合成前端体验优化方案

## 背景

当前语音合成界面位于 `web/src/components/VoiceSynthModal.vue`。它已经支持选择已有文本、手动粘贴、默认音色描述、音色润色、单段合成、选中组合、批量 ZIP、同步包生成等功能。

这些能力本身有价值，但现在集中在一个 800px 弹窗中，界面更像“功能调试台”，而不是一个稳定的语音生产流程。用户进入弹窗后会同时面对多个按钮和多种生成方式，很难判断推荐操作路径。

结合语音合成重构方案，本次前端优化的核心目标是：让用户先确认“这是谁在说话”，再生成“这段内容怎么说”。界面应该默认帮助用户获得音色统一、可用于视频剪辑的完整同步包，而不是鼓励用户逐字幕段调整音色。

## 当前问题

### 1. 使用逻辑不够线性

现在的实际路径是：

```text
选择文本 / 粘贴文本
-> 自动分段
-> 填写默认音色
-> 可选润色
-> 可选应用到全部
-> 可选逐段改音色
-> 可选选中组合
-> 可选单段合成
-> 可选全部生成 ZIP
-> 可选生成同步包
```

这个流程的问题是：所有能力同时暴露，但没有主次。新用户不知道应该点“全部生成 ZIP”还是“生成同步包”；老用户在长文本下也会被大量片段、输入框和按钮分散注意力。

### 2. 主按钮和辅助按钮混在一起

当前头部操作区同时放置：

- 合成选中
- 全部生成 (ZIP)
- 生成同步包
- 清除音频

其中“生成同步包”才是最符合视频剪辑工作流的主动作，但它和其他按钮视觉权重接近。`全部生成 (ZIP)` 容易被误解为推荐路径，实际它是逐字幕段音频包，更偏调试或特殊导出。

### 3. “合成选中”命名不准确

界面上的“合成选中”实际行为是把连续片段组合成一个 group，并不会立即生成音频。这个命名会造成预期落差。更准确的表达是：

- `组合为语音块`
- `合并为一句`
- `创建语音块`

### 4. 音色逻辑鼓励割裂

当前每个字幕段都有独立的 `voiceDescription` 输入框。这个设计看似灵活，但会鼓励用户逐段改音色，导致整篇音频更容易割裂。

更合理的逻辑是：

- 默认只维护一个全局音色档案。
- 语音块只允许添加轻量语气备注。
- 逐段音色覆盖放入高级模式，不作为默认界面。

### 5. 同步包生成与用户编辑内容可能不一致

当前 `handleSyncPackage` 使用 `segments.value.map(seg => seg.text).join('')` 拼回全文。因为字幕分段会去掉部分标点，这会造成同步包 TTS 文本不再等于用户原文，可能影响停顿、语气和自然度。

优化后应保存原始输入内容，例如 `sourceContent`，同步包和智能语音块规划都基于原文，而字幕段只用于显示和时间轴。

### 6. 视觉层级偏平

界面中音色、分段、播放器、生成按钮都在同一层级。长文本场景下，片段列表会占据大部分注意力，但用户最需要确认的是：

- 当前选中了哪篇文本？
- 音色是否已经确认？
- 会生成多少个语音块？
- 最终导出的是什么？
- 还能不能直接点主按钮？

这些状态目前没有形成稳定的顶部摘要或底部操作栏。

## 优化目标

1. 让语音合成从“多按钮面板”变成“清晰生产流程”。
2. 默认引导用户生成完整音频、同步字幕和 manifest。
3. 降低逐段音色编辑的存在感，减少音色割裂。
4. 让试听确认成为批量生成前的关键步骤。
5. 在长文本、多片段、多语音块场景下保持界面可扫描。
6. 保留高级能力，但不让它们打扰主流程。

## 推荐信息架构

将界面改为四步工作流：

```text
1. 选择文本
2. 设定音色
3. 试听确认
4. 生成同步包
```

### Step 1：选择文本

保留两种来源：

- 选择已有文本
- 手动粘贴

加载后显示摘要，而不是立刻把所有字幕段铺满：

```text
《文本标题》
共 1280 字 / 76 条字幕段 / 9 个语音块
```

这里应该同时生成：

- `sourceContent`：原始全文。
- `subtitleSegments`：短字幕段。
- `speechChunks`：智能语音块。

### Step 2：设定音色

把“默认音色描述”升级为“音色档案”。

推荐字段：

- 音色名称
- 基础描述
- 负向约束
- 语速
- 情绪
- 场景

第一阶段可以保持一个文本框，但 UI 文案应从“默认音色描述”改成“音色档案”，并明确这是整篇音频统一使用的声音。

按钮建议：

- `优化描述`
- `保存为预设`
- `使用原描述`

不建议继续显示“应用到全部”。在新的心智中，全局音色天然应用到全部。

### Step 3：试听确认

新增固定试听区：

```text
试听文案：
今天我们来聊一个很实用的方法。它听起来简单，但真正做好并不容易。你可能会问，第一步应该从哪里开始？
```

用户操作：

- 点击 `生成试听`
- 播放试听音频
- 点击 `确认使用这个音色`

确认前，主生成按钮可以禁用，或显示低优先级提示。这样能显著降低“整篇生成后才发现声音不对”的成本。

### Step 4：生成同步包

默认主按钮：

```text
生成同步包
```

同步包内容：

- 完整音频 WAV
- 同步字幕 SRT
- manifest.json
- 语音块 chunks

高级导出放入折叠菜单：

- 导出逐字幕段 ZIP
- 只生成当前语音块
- 重新生成失败语音块
- 导出语音块清单

## 推荐布局

### 弹窗尺寸

当前 `width="800px"` 对长文本语音生产偏窄。建议：

- 桌面端：`width="1040px"` 或 `min(1040px, calc(100vw - 48px))`
- 内容最高：`calc(100vh - 160px)`
- 底部操作栏 sticky

### 页面结构

```text
┌────────────────────────────────────────────┐
│ 语音合成                         状态摘要 │
├────────────────────────────────────────────┤
│ Stepper: 选择文本 -> 音色 -> 试听 -> 生成  │
├──────────────────────┬─────────────────────┤
│ 左侧：当前步骤主表单 │ 右侧：预览与状态    │
│                      │                     │
│ 文本选择/音色档案    │ 字幕段/语音块摘要   │
│ 试听播放器           │ manifest 预览       │
├──────────────────────┴─────────────────────┤
│ sticky footer: 高级选项        生成同步包 │
└────────────────────────────────────────────┘
```

### 视觉层级

主区域只突出一个当前任务。比如在“音色”步骤，片段列表不要抢占视觉中心，只显示摘要：

```text
已规划 9 个语音块
平均每块约 142 字
预计导出完整音频 + SRT
```

用户展开“查看语音块”后再看到列表。

## 组件拆分建议

当前 `VoiceSynthModal.vue` 负责过多。建议拆成：

```text
web/src/components/voice-synth/VoiceSynthModal.vue
web/src/components/voice-synth/SourceStep.vue
web/src/components/voice-synth/VoiceProfileStep.vue
web/src/components/voice-synth/AuditionStep.vue
web/src/components/voice-synth/GenerateStep.vue
web/src/components/voice-synth/SpeechChunkPreview.vue
web/src/components/voice-synth/SubtitleSegmentPreview.vue
web/src/components/voice-synth/AdvancedExportMenu.vue
```

状态可以先继续放在父组件中，不急着引入新 store。等后续加入历史任务、音色预设、任务恢复后，再考虑拆成 `useVoiceSynthSession()` composable。

## 状态模型建议

新增前端状态：

```js
const sourceContent = ref('')
const subtitleSegments = ref([])
const speechChunks = ref([])
const activeStep = ref('source')
const voiceProfile = ref({
  rawDescription: '',
  canonicalPrompt: '',
  negativePrompt: '',
  confirmed: false,
})
const audition = ref({
  generating: false,
  audioUrl: null,
  confirmed: false,
})
const generation = ref({
  mode: 'sync-package',
  loading: false,
  progressText: '',
})
```

主按钮可用条件：

```text
有 sourceContent
有 voiceProfile.rawDescription 或 canonicalPrompt
有 ttsKey
音色已试听确认，或用户明确选择跳过试听
当前未生成中
```

## 交互文案建议

### 按钮命名

| 当前文案 | 建议文案 | 原因 |
|----------|----------|------|
| 默认音色描述 | 音色档案 | 强调全局统一 |
| 润色 | 优化描述 | 更贴近用户语言 |
| 应用到全部 | 移除 | 全局音色默认应用全部 |
| 合成选中 | 组合为语音块 | 行为更准确 |
| 全部生成 (ZIP) | 导出逐段音频 | 降低主路径误导 |
| 生成同步包 | 生成同步包 | 保留为主动作 |
| 合成一句话 | 生成当前语音块 | 和智能分块概念一致 |

### 状态提示

推荐使用短状态，而不是长说明：

- `未选择文本`
- `音色待确认`
- `已确认音色`
- `已规划 9 个语音块`
- `正在生成第 3/9 个语音块`
- `同步包已生成`

## 高级能力的收纳方式

以下功能不应默认铺开：

- 逐字幕段音色覆盖
- 逐字幕段合成
- 手动组合片段
- 导出逐段 ZIP
- 清除所有音频

建议放入“高级”折叠区：

```text
高级
- 手动编辑语音块
- 逐字幕段调试
- 导出逐段音频
- 清除临时音频
```

这样既保留专业用户能力，又不影响普通用户完成主流程。

## 视觉风格建议

当前项目是黑白克制的“墨 · 影”风格，语音合成界面也应延续这个方向。优化重点不在增加颜色，而在增加结构。

建议：

1. 保持单色体系，但用灰阶区分层级。
2. 主按钮只保留一个黑色实心按钮。
3. 次要操作使用文本按钮或下拉菜单。
4. 音频播放器不要在每条字幕下默认出现，改成当前选中块的试听区。
5. 分段列表使用紧凑表格或可展开列表，不使用大量重复卡片。
6. 语音块用轻量编号和范围展示，例如 `语音块 03 · 字幕 18-26 · 156 字`。

## 分阶段优化

### Phase 1：低风险整理

- 保留现有弹窗和接口。
- 新增 `sourceContent`，同步包不再从字幕段反推全文。
- 调整按钮文案和层级。
- 将 `全部生成 ZIP`、`清除音频` 收到高级区。
- 将“合成选中”改为“组合为语音块”。
- 主按钮只突出“生成同步包”。

### Phase 2：工作流化

- 引入步骤条：文本、音色、试听、生成。
- 新增试听确认状态。
- 默认隐藏逐段音色输入。
- 增加语音块摘要和可展开预览。
- 生成按钮根据状态精确禁用。

### Phase 3：音色档案化

- 新增 VoiceProfile UI。
- 支持音色预设、最近使用、负向约束。
- 后端接入 canonical prompt。
- 支持试听候选和确认后的批量生成。

## 验收标准

1. 用户首次打开语音合成界面，能明确知道下一步该做什么。
2. 页面中只有一个最高优先级主按钮。
3. 默认流程不会鼓励逐字幕段改音色。
4. 生成同步包使用原始全文，而不是从字幕段拼回的文本。
5. 长文本下界面仍能快速看到字数、字幕段数、语音块数。
6. 高级用户仍能找到逐段调试和导出能力。
7. 视觉风格与现有黑白克制主题一致，不引入额外复杂色彩。

## 推荐结论

当前语音合成界面不需要先做大规模视觉重绘。更重要的是先调整信息架构：

- 把“生成同步包”确立为主路径。
- 把“音色档案 + 试听确认”放到批量生成前。
- 把逐段合成和逐段音色覆盖收纳为高级能力。
- 把字幕段和语音块分开展示。

完成这些调整后，界面会从“能操作很多功能”变成“能稳定产出可用语音素材”。这比单纯优化按钮样式更能提升用户体验。
